## Post-merge

- [ ] Review and authorize candidate, commit, push, and create PR `release/v1.1.0` → `main`.
- [ ] Merge the reviewed PR.
- [ ] Record exact merged main SHA.
- [ ] Verify main contains only the reviewed release-preparation changes relative to the starting commit.

## Post-deploy

- [ ] Publish/sync that exact main through Lovable.
- [ ] Verify the public application serves the current v1.1.0 candidate.
- [ ] Complete public production smoke, including download/import and Application/Source/Issues links.
- [ ] Record the exact deployed main SHA and successful public-smoke evidence.

## Tag / GitHub Release

- [ ] Only after public smoke passes, create annotated tag `v1.1.0` at the exact proven deployed main SHA.
- [ ] Push the tag.
- [ ] Create GitHub Release with [v1.1.0.md](v1.1.0.md) as its body.
- [ ] Verify stable/latest, not prerelease.
- [ ] Recheck Application / Source / Issues links.

If deployment needs a corrective commit, do not tag the old candidate. Fix narrowly on a reviewed branch, merge, redeploy, repeat public smoke, and tag only the corrected proven production commit. No post-merge, deployment, tag, or GitHub Release step is completed during local preparation.
