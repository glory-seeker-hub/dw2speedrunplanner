# Digimon World 2 Run Planner & Battle Simulator v1.2.0

## Highlights

- Capture-aware battle optimization: require the selected Enemy to be the last Enemy defeated.
- Run Planner automatically carries recorded capture targets into Analyze Battle. Manual Encounter simulations offer optional capture target selection.
- Random and Optimized simulation distinguish mechanical battle wins from capture-qualified victories. Fastest Potential selects the fastest capture-qualified victory found; Average Victory evaluates capture-qualified victories; Success Rate requires both Player victory and the correct capture outcome.
- Results and Simulation Reports identify the Capture Target, Last Enemy Defeated, Capture Success Rate, and Satisfied / Failed status. Battle Win Rate remains a separate metric.
- About this application and How to Use explain the capture objective and the rightmost simultaneous-KO rule: **E3 > E2 > E1**.

## Capture behavior

A capture target must be the last Enemy defeated. A battle can still mechanically be a Player victory when another Enemy is defeated last. The battle outcome remains a Player victory, but the capture objective is Failed and that execution does not count as a capture-qualified search success.

If one resolved action defeats multiple Enemies simultaneously, the rightmost defeated Enemy determines the capture result: **E3 > E2 > E1**. This is a capture tie-break, not a claim that E3 receives damage later. Across separate actions, the later Enemy KO determines the result.

Targets use combatant position and encounter slot, so duplicate species remain distinguishable. Changing the manual encounter clears the previous target. With no capture objective, simulation retains its ordinary battle-win behavior.

## Limitations

Optimized Search is bounded and sampled; it does not guarantee the global optimum. Finding no capture-qualified route within the configured search effort does not prove that none exists. TAS Luck controls only supported modeled RNG outcomes.

Battle frames exclude external menu/order-entry overhead. Player HP/MP depletion does not stop the offensive simulation; required recovery, revival, Guard and item actions are not automatically inserted or counted.

Planner data is browser-local. Backups are explicit local JSON files; there are no accounts, cloud synchronization or automatic backups. Export Route and Simulation Report are not restorable Planner backups.

Application version **1.2.0** is independent of **Planner schema v7**, **Simulation Report v1**, and **Backup Format v1**, which remain unchanged.
